# Требования к информационной системе электронной очереди

## 1. Общие сведения

**Наименование проекта:** информационная система электронной очереди.

**Вариант задания:** М.

**Назначение системы:** автоматизация организации и управления очередью посетителей в учреждениях, где необходимо упорядочить приём граждан или клиентов.

**Цель разработки:** спроектировать информационную систему, которая позволяет регистрировать посетителей в очереди, присваивать им номера, отображать текущий номер обслуживания и предоставлять сотрудникам инструменты управления очередью.

## 2. Основания для разработки

Основанием для разработки является индивидуальное задание по дисциплине «Проектная деятельность в ИТ» — вариант М: «Разработка информационной системы электронно-информационной очереди».

Необходимость разработки обусловлена потребностью в упорядочивании обслуживания посетителей, сокращении путаницы при ожидании и повышении удобства работы сотрудников.

## 3. Область применения

Система может применяться в государственных учреждениях, медицинских организациях, банках, учебных заведениях и сервисных центрах, где посетители обслуживаются в порядке электронной очереди.

## 4. Категории пользователей

### 4.1. Посетитель
- Получает номер очереди.
- Узнаёт состояние своей очереди.
- Следит за отображением текущего номера обслуживания.

### 4.2. Оператор
- Вызывает следующего посетителя.
- Просматривает текущую очередь.
- Отмечает завершение обслуживания.
- При необходимости повторно вызывает посетителя.

### 4.3. Администратор
- Управляет настройками системы.
- Настраивает категории обслуживания и рабочие места.
- Управляет учётными записями сотрудников.
- Контролирует корректность работы системы.

## 5. Функциональные требования

Система должна обеспечивать следующие функции:

1. Регистрация нового посетителя в очереди.
2. Автоматическое присвоение уникального номера очереди.
3. Отображение текущего номера и состояния очереди.
4. Вызов следующего посетителя оператором.
5. Завершение обслуживания посетителя.
6. Повторный вызов посетителя при необходимости.
7. Разграничение функций в зависимости от роли пользователя.
8. Сохранение информации о действиях с очередью в течение работы системы.
9. Обработка ошибочных действий пользователя и отображение понятных сообщений.

## 6. Нефункциональные требования

- **Удобство использования:** интерфейс должен быть понятен посетителям и сотрудникам.
- **Надёжность:** система должна корректно обрабатывать операции с очередью.
- **Производительность:** основные операции должны выполняться без заметных задержек при обычной нагрузке.
- **Безопасность:** доступ к административным функциям должен предоставляться только уполномоченным пользователям.
- **Сопровождаемость:** структура проекта должна позволять изменять и дополнять функциональность.
- **Совместимость:** веб-версия системы должна корректно отображаться в современных браузерах, если проект реализуется как веб-приложение.

## 7. Ограничения и допущения

На текущем этапе проект представляет собой учебную разработку. Конкретные технологии, база данных и способ развёртывания будут определены на последующих этапах проектирования.

Фактическая работающая система не считается реализованной только на основании данного описания. Функциональность должна быть подтверждена реализацией и тестированием.

## 8. Иерархическая структура работ (ИСР)

Работы по проекту распределяются по этапам жизненного цикла информационной системы:

1. **Анализ требований**
   - Определение проблемы и цели проекта.
   - Определение категорий пользователей.
   - Формирование функциональных и нефункциональных требований.

2. **Проектирование**
   - Проектирование сценариев работы посетителя.
   - Проектирование рабочего места оператора.
   - Проектирование функций администратора.
   - Разработка структуры данных и интерфейсов.

3. **Реализация**
   - Подготовка структуры исходного кода.
   - Разработка механизма управления очередью.
   - Разработка пользовательского интерфейса.
   - Реализация разграничения прав доступа.

4. **Тестирование**
   - Проверка выдачи номера очереди.
   - Проверка вызова и завершения обслуживания.
   - Проверка обработки ошибок.
   - Проверка разграничения доступа.

5. **Внедрение и сопровождение**
   - Подготовка инструкции пользователя.
   - Подготовка проекта к развёртыванию.
   - Исправление выявленных недостатков.

Проект считается подготовленным к демонстрации, когда:

- изменения сохраняются в истории Git;
- разработанные функции проходят соответствующие проверки после реализации.
